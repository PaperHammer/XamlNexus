# XamlNexus project manifest

[English](project-manifest.md) | [简体中文](project-manifest.zh-CN.md)

Every project generated by XamlNexus contains an `xamlnexus.json` file in the
solution root. It is the machine-readable contract used by `add`,
`list`, `validate`, `doctor`, and `upgrade` commands.

## Schema version 1

```json
{
  "schemaVersion": 1,
  "generatorVersion": "1.0.3",
  "project": {
    "name": "MyApp",
    "preset": "winui",
    "profile": "standard",
    "language": "en-US",
    "solutionFormat": "sln"
  },
  "modules": [
    {
      "id": "editorconfig",
      "version": "1.0.0",
      "source": "recipe",
      "files": [
        {
          "path": ".editorconfig",
          "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
        }
      ]
    }
  ],
  "scaffoldFiles": [
    {
      "path": "Directory.Build.props",
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "baselineContentGzipBase64": "H4sI..."
    },
    {
      "path": "MyApp.UI/App.xaml.cs",
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "baselineContentGzipBase64": "H4sI...",
      "userEditable": true
    }
  ]
}
```

- `schemaVersion` identifies the manifest structure. A tool must refuse to
  modify a manifest with a newer, unsupported schema.
- `generatorVersion` is the XamlNexus CLI version that last generated the
  project structure.
- `project.preset` is `winui` or `hybrid`.
- `project.profile` is the starting capability profile: `standard` (default) or
  `basic`. Legacy manifests may omit it and are treated as standard. It records
  creation intent, not the current installed modules, and does not change on add/remove.
- `project.language` is the default generated application language.
- `project.solutionFormat` is `sln` (default) or `slnx`.
- `modules` records the capabilities managed by XamlNexus. Module IDs are
  case-insensitively unique.
- A module `source` is `template` for a built-in preset capability or `recipe`
  for a module installed through a Recipe, including during project composition.
- A module `version` records the XamlNexus or Recipe version that owns its
  generated files and migration rules.
- Recipe modules include their owned files and SHA-256 values. This allows
  validation and future remove/upgrade operations to detect user changes.
- `scaffoldFiles` records files originating from the template. SHA-256 protects
  the recorded baseline, while optional `baselineContentGzipBase64` supplies
  the exact compressed base input for future three-way merges.
- `userEditable: true` identifies source and project files that users and
  Recipes normally customize. `validate` does not treat those customizations
  as damage; `upgrade` still plans them against their stored baseline.
- `userEditable` is a legacy diagnostic hint, not an editing permission.
  Files with `false` or an omitted value can also be customized: content
  differences produce a warning, not an error. Keep the original hashes;
  automatic updates and removals use them to protect local changes.
- Older hash-only entries remain valid and use conservative conflict behavior
  when their local content no longer matches the hash.

The file is intentionally deterministic: it contains no timestamp, machine
path, user name, or other environment-specific value. It should be committed
to version control with the generated solution.

Use `xamlnexus list` to display the project identity and managed modules. Use
`xamlnexus validate` to validate the manifest and the key files owned by each
module. Both commands search for `xamlnexus.json` from the current directory up
through its parents, or accept an explicit `--project <path>` argument.

XamlNexus validates the complete manifest before saving it and writes through
a temporary file before atomically replacing the destination. Commands that
change project capabilities must update source files and this manifest as one
transaction.

The transaction and compatibility rules for installable modules are defined in
the [Recipe contract](recipe-contract.md).

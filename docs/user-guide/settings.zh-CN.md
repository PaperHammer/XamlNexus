# 设置行为

[English](settings.md) | [简体中文](settings.zh-CN.md)

生成应用通过 `IUserSettingsClient.SaveAsync<ISettings>()` 持久化设置。内置控件捕获保存失败、报告错误并恢复可用。语言切换即时更新已有控件，见[本地化](localization.zh-CN.md)。

JSON 保存先在同目录写完整临时文件，再替换旧文件；序列化或替换失败保留原文件，并尝试删除临时文件。

## 损坏设置恢复

两种架构和 Showcase 在文件缺失时创建默认设置。JSON 格式错误（包括 null 文档）会先逐字节备份为同目录的 `<settings-file>.corrupt.<UTC timestamp>.<unique id>.bak`，再保存默认值。日志记录备份位置，备份不自动清理。备份失败则停止恢复且不替换原文件；默认值保存失败也保留备份，不截断原文件。

文件锁、权限等非 JSON 读取错误直接传给调用方，不触发重置。有效设置只加载，不重写。

恢复时关闭应用及混合后台，在设置旁找到备份，修复 JSON 或将需要的值复制到当前文件。编辑前保留副本，保存后重启。原样恢复损坏 JSON 会再次触发恢复。目前没有恢复 UI，也不提供每个设置值的语义校验。

## 存储目录

两种架构都先将文件复制到独立空目录，再保存新路径。拒绝路径重叠、目标已有内容以及源树中的链接；不能复制正在被写入的文件。

成功后原文件仍保留。复制或设置保存失败恢复旧配置路径，但目标可能残留部分或完整副本。请自行检查，再用空目录重试；应用不会在失败时清空目标。这是文件复制，不是对并发变化数据的一致性备份。

SQLite Recipe 有独立数据库位置；修改此设置不会迁移活动数据库，需要使用数据库专用备份和迁移操作。

## 主题与背景材质

保存失败会恢复旧选择，主题还会恢复已应用的旧主题。保存的背景材质在下次应用启动生效。

## 登录自启动（纯 WinUI）

打开设置会读取当前 Windows 启动注册，读取和修改期间禁用开关。保存失败会尝试恢复之前注册并报告错误。非打包应用的回滚保留原命令，而非重新生成替代命令。

非打包应用使用当前用户 Run 注册表键中的自身条目。仅有注册不能证明登录后一定运行，Windows 启动批准和策略仍可能影响执行。打包应用使用 StartupTask，系统阻止请求时报告原因。

混合架构保留已有后台启动流程，上述纯 WinUI 行为不替换混合流程。

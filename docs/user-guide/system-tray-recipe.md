# System tray Recipe

[English](system-tray-recipe.md) | [简体中文](system-tray-recipe.zh-CN.md)

Install the optional desktop integration module into a generated pure WinUI
project:

```powershell
xamlnexus add tray --project <project-directory>
```

The Recipe adds `Modules/SystemTrayModule.cs` to the UI project and references
the .NET 8-compatible `H.NotifyIcon.WinUI` 2.3.2 package. At startup it creates
a native notification-area icon with:

- left-click show/hide behavior;
- a WinUI Fluent context menu with **Show / Hide** and **Exit** commands;
- a close-window dialog offering **Close window** (hide to tray), **Exit application**, and **Cancel**;
- deterministic disposal when the application shuts down.

The close dialog defaults to asking every time. **Remember my choice** persists
the selection in the normal user settings JSON as `WindowCloseBehavior`:
`"Ask"`, `"HideToTray"`, or `"Exit"`. The tray menu's **Exit** command always exits.
Notifications remain available through `ShowNotification`; no balloon is shown
automatically on startup.

When `settings` is present, its general settings page shows **When closing the
main window**. The control appears whether settings or tray was installed first,
and disappears after tray is removed and the app is rebuilt. Without settings,
the close dialog still works and can remember a choice.

Stop the app, rebuild, and restart after changing Recipes. H.NotifyIcon's
`SecondWindow` mode renders the WinUI flyout even while the main window is hidden;
this mode is marked as preview by the upstream library.

Exiting hides the main window before window and service cleanup, so the window
does not remain visible during cleanup. Cancelling the close dialog keeps it visible.

XamlNexus remains at the unreleased 1.0.4 version, and these Recipes remain at 1.0.0.
Projects generated by an earlier development build may lack the close-settings
contract. Regenerate disposable test projects with the latest build, or manually
migrate existing scaffold changes while preserving user code. A same-version
`upgrade` or `update` is not a way to refresh those development projects.

The generated `SystemTrayService` is registered as a singleton. Code created
through the application service provider can request it by constructor
injection and publish notifications without depending directly on the tray
control:

```csharp
public sealed class SyncJob(SystemTrayService tray) {
    public void Complete() =>
        tray.ShowNotification("Sync complete", "All local files are up to date.");
}
```

The Recipe currently supports the `winui` Preset. The hybrid Preset already
contains a WPF-owned tray process, so installing a second tray owner there is
intentionally rejected.

`xamlnexus remove tray` deletes the generated module when it is still
unchanged. As with other ensured package references, the NuGet reference is
retained because the project or another module may also use it.
